Angular has one of the largest and most active communities in the web development ecosystem. Whether you're just starting out or looking for advanced topics, these resources will help you level up.

## 🏛️ Official Resources

### Angular Team

- **[angular.dev](https://angular.dev)** — The official Angular documentation site. Completely rewritten with interactive tutorials, API reference, and best practices guides.
- **[Angular Blog](https://blog.angular.dev)** — Official blog with release announcements, feature deep-dives, and roadmap updates.
- **[Angular GitHub](https://github.com/angular/angular)** — The source code, issue tracker, and RFCs for Angular itself.
- **[Angular CLI GitHub](https://github.com/angular/angular-cli)** — Source code for the Angular CLI, Schematics, and build system.
- **[Angular YouTube Channel](https://www.youtube.com/@Angular)** — Official tutorials, conference talks, and Angular release overviews.

### Key Documentation Pages

- **[Getting Started Tutorial](https://angular.dev/tutorials)** — Interactive, step-by-step tutorial for building your first Angular app.
- **[Developer Guides](https://angular.dev/guide)** — In-depth guides on signals, forms, routing, HTTP, testing, and more.
- **[API Reference](https://angular.dev/api)** — Complete API documentation for all Angular packages.
- **[CLI Reference](https://angular.dev/cli)** — Full reference for all Angular CLI commands and options.
- **[Angular Update Guide](https://angular.dev/update-guide)** — Step-by-step migration guide between Angular versions.

## 💬 Community Forums

### Get Help

- **[Stack Overflow — `angular` tag](https://stackoverflow.com/questions/tagged/angular)** — The go-to place for specific technical questions. Search before asking — most common issues have answers.
- **[Angular Discord](https://discord.gg/angular)** — Official community Discord server with channels for help, discussions, and job postings.
- **[Reddit r/Angular](https://www.reddit.com/r/Angular2/)** — Active subreddit for Angular news, discussions, and questions (note: the sub is `Angular2` but covers all modern versions).
- **[GitHub Discussions](https://github.com/angular/angular/discussions)** — For longer-form discussions, feature requests, and architectural questions.

### Stay Updated

- **[X/Twitter @Angular](https://twitter.com/angular)** — Official Angular account with release announcements and community highlights.
- **[Angular Blog RSS](https://blog.angular.dev/feed)** — Subscribe to the blog via RSS for automatic updates.

:::tip
When asking for help on Stack Overflow or Discord, always include: your Angular version, a minimal reproduction (StackBlitz is great), the full error message, and what you've already tried.
:::

## 📦 Notable Open-Source Projects

### UI Component Libraries

- **[Angular Material](https://material.angular.io/)** — Official Material Design component library by the Angular team. The gold standard for Angular UI components.
- **[Angular CDK](https://material.angular.io/cdk)** — Component Dev Kit — behavior primitives (drag-drop, virtual scroll, overlays) without Material Design styling.
- **[Spartan UI](https://www.spartan.ng/)** — Accessible, unstyled Angular components inspired by shadcn/ui. Built for Tailwind CSS.
- **[PrimeNG](https://primeng.org/)** — Feature-rich UI component library with 80+ components and multiple themes.
- **[Ng-Zorro](https://ng.ant.design/)** — Ant Design components for Angular.
- **[Taiga UI](https://taiga-ui.dev/)** — Comprehensive UI kit with Angular-first design.

### State Management

- **[NgRx](https://ngrx.io/)** — Redux-inspired reactive state management with stores, effects, and entity adapters. The most popular Angular state management library.
- **[NGXS](https://www.ngxs.io/)** — Simpler state management using classes and decorators.
- **[Elf](https://ngneat.github.io/elf/)** — Reactive store based on RxJS with a functional API.

### Meta-Frameworks and Tools

- **[Analog](https://analogjs.org/)** — The fullstack Angular meta-framework. Adds file-based routing, API routes, SSR/SSG, and Vite support to Angular.
- **[Nx](https://nx.dev/)** — Monorepo build system with first-class Angular support. Excellent for large-scale projects with multiple apps and libraries.
- **[Scully](https://scully.io/)** — Static site generator for Angular apps (primarily for Angular sites that need pre-rendered pages).

### Testing

- **[Angular Testing Library](https://testing-library.com/docs/angular-testing-library/intro/)** — Test Angular components from a user perspective rather than implementation details.
- **[Spectator](https://ngneat.github.io/spectator/)** — Simplifies Angular unit testing with a more expressive API on top of TestBed.
- **[ng-mocks](https://ng-mocks.sudo.eu/)** — Powerful mocking library for Angular tests — auto-mock components, directives, pipes, and services.

### Utilities

- **[ngx-translate](https://github.com/ngx-translate/core)** — Internationalization (i18n) library for Angular.
- **[ngx-formly](https://formly.dev/)** — Dynamic form generation from JSON schemas.
- **[angular-oauth2-oidc](https://github.com/manfredsteyer/angular-oauth2-oidc)** — OAuth 2.0 and OpenID Connect support.

## 🤝 Contributing to Angular

Angular is open source and welcomes contributions:

1. **Read the [Contributing Guide](https://github.com/angular/angular/blob/main/CONTRIBUTING.md)** — Understand the contribution process, coding standards, and commit message format.

2. **Find starter issues** — Look for issues labeled [`good first issue`](https://github.com/angular/angular/labels/good%20first%20issue) on GitHub.

3. **Participate in RFCs** — Major Angular features start as RFCs (Request for Comments) in the [Angular discussions](https://github.com/angular/angular/discussions). Your feedback shapes the framework's direction.

4. **Improve documentation** — The [angular.dev](https://github.com/angular/angular/tree/main/adev) docs are part of the Angular repository. Documentation improvements are always welcome.

5. **Build and share tools** — Create and publish libraries, schematics, or tools that help the community.

:::note
You don't have to write code to contribute! Filing detailed bug reports, answering questions on Stack Overflow, and writing blog posts are all valuable contributions to the Angular ecosystem.
:::
